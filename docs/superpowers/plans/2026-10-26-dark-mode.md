# Dark mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a person choose light or dark for the capture desk, and restore that choice from localStorage on the next visit.

**Architecture:** The choice lives on the existing settings record as `theme: "light" | "dark"`. An inline script in `index.html` sets `data-theme` on `<html>` before React paints. React reads the same record, and a top-bar button writes it back. Dark mode is a second set of the CSS variables already used by the desk. The first visit stays light. The app does not follow the operating system.

**Tech Stack:** TypeScript, Vitest, React 19, Vite, existing `personal-os.settings.v1` localStorage record in `apps/capture/src/store/settingsStore.ts`.

## Global Constraints

- Local-first version 1. No accounts, hosted storage, or sync. The choice stays in this browser.
- Default mode is light. A missing or invalid `theme` value is light.
- Saving the mode must not wipe LLM settings, and saving LLM settings must not wipe the mode.
- Clear browser cache deletes notes and custom shelves only. The mode stays, because it lives in `personal-os.settings.v1` with the LLM settings.
- Do not edit `AGENTS.md` or `docs/agent-kb/` in these tasks. After the last task, ask whether those files need a sentence about the saved appearance.

## File structure

- `apps/capture/src/store/settingsStore.ts` — `ColorMode`, `loadColorMode`, `saveColorMode`. `AppSettings` gains `theme`.
- `apps/capture/src/store/settingsStore.test.ts` — persistence tests.
- `apps/capture/index.html` — inline script applies the saved mode before paint, and updates `theme-color`.
- `apps/capture/src/theme.ts` — `applyColorMode` sets `document.documentElement.dataset.theme` and the `theme-color` meta tag. Shared by startup and the toggle.
- `apps/capture/src/theme.test.ts` — applies `data-theme` and the meta color.
- `apps/capture/src/App.tsx` — top-bar toggle beside the desk menu.
- `apps/capture/src/App.test.tsx` — toggle writes localStorage and survives a remount.
- `apps/capture/src/styles.css` — `:root[data-theme="dark"]` variables, `--on-primary`, and the light-only hex colors moved onto variables.

In `apps/capture/src/store/settingsStore.ts`, extend the settings type and the reader, then add the two functions.

```ts
export type ColorMode = "light" | "dark";

export type AppSettings = {
  llm: LlmSettings;
  theme: ColorMode;
};

const DEFAULT_SETTINGS: AppSettings = {
  llm: DEFAULT_LLM_SETTINGS,
  theme: "light",
};

function colorMode(value: unknown): ColorMode {
  return value === "dark" ? "dark" : "light";
}
```

Inside `readRaw`, keep the current LLM merge and set `theme: colorMode(record.theme)`.

```ts
export function loadColorMode(): ColorMode {
  return readRaw().theme;
}

export function saveColorMode(theme: ColorMode): ColorMode {
  const settings = readRaw();
  settings.theme = theme;
  writeRaw(settings);
  return settings.theme;
}
```

`saveLlmSettings` already copies the whole settings object before replacing `llm`, so the saved theme stays.

- [ ] **Step 3: Write the minimal implementation**

Create `apps/capture/src/theme.ts`:

```ts
import { loadColorMode, type ColorMode } from "./store/settingsStore.js";

const THEME_COLOR: Record<ColorMode, string> = {
  light: "#fff8f5",
  dark: "#1c1917",
};

export function applyColorMode(theme: ColorMode): void {
  document.documentElement.dataset.theme = theme;
  document
    .querySelector('meta[name="theme-color"]')
    ?.setAttribute("content", THEME_COLOR[theme]);
}

applyColorMode(loadColorMode());
```

The module applies the stored mode as soon as it is imported, so a React remount is not required for the first paint inside the app. The inline script below covers the moment before that module loads.

In `apps/capture/src/main.tsx`, import the theme module before the app:

```ts
import "./bufferGlobal";
import "./theme";
import { StrictMode } from "react";
import { createRoot } from "react-dom/client";
import App from "./App";
import "./styles.css";
```

In `apps/capture/index.html`, put this script immediately before `<div id="root">`. It only reads `personal-os.settings.v1` and sets the same attribute. It does not write storage.

```html
<script>
  try {
    var raw = localStorage.getItem("personal-os.settings.v1");
    var theme = raw && JSON.parse(raw).theme === "dark" ? "dark" : "light";
    document.documentElement.dataset.theme = theme;
    var meta = document.querySelector('meta[name="theme-color"]');
    if (meta) meta.setAttribute("content", theme === "dark" ? "#1c1917" : "#fff8f5");
  } catch (error) {}
</script>
```

- [ ] **Step 3: Write the minimal implementation**

In `apps/capture/src/App.tsx`, import `loadColorMode`, `saveColorMode`, and `applyColorMode`. Hold the mode in state initialized from `loadColorMode()`.

```tsx
const [colorMode, setColorMode] = useState(loadColorMode);

function toggleColorMode() {
  const next = colorMode === "dark" ? "light" : "dark";
  saveColorMode(next);
  applyColorMode(next);
  setColorMode(next);
}
```

Render this button as the first child of `<div className="topbarTools">`, before the desk menu button:

```tsx
<button
  type="button"
  className="iconButton"
  aria-label={colorMode === "dark" ? "Use light mode" : "Use dark mode"}
  aria-pressed={colorMode === "dark"}
  onClick={toggleColorMode}
>
  {colorMode === "dark" ? "Light" : "Dark"}
</button>
```

The visible word is enough for this task. A later visual pass can swap it for an icon if the word crowds the bar. The accessible name stays `Use dark mode` or `Use light mode`.
